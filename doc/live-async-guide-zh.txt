FFmpeg 7.0.3 异步低延迟改造指导（供内网/外部小模型执行）
====================================================

1. 交付对象与边界
----------------
基线：n7.0.3，eaddd1d7140bab19e5a4403d3c0f61fe5f59cb75。
分支：Nakiha/FFmpeg 的 live/n7.0.3-async-early-output。
公开头文件：libavcodec/async.h，AVCODEC_ASYNC_API_VERSION == 1。
本分支 libavcodec 为 61.4.100；原版为 61.3.100。这是自定义扩展 API。

目标：最多 N 个帧任务并行，按原顺序尽早输出，前台数据 API 不等待解码。
每路增加一个协调线程。前台队列有短互斥锁和引用操作，不是无锁或硬实时。
flush/free 等生命周期操作会等待。普通旧接口仍有原来的流水线行为。

仅支持原生软件 h264/hevc，实际 FF_THREAD_FRAME，线程数 > 1，默认
get_format，无硬件设备/帧上下文。创建必须在首次输入/EOF 前进行。
B 帧重排、参考依赖、实际计算和下游积压的延迟仍然存在。

2. 源码移植清单
---------------
优先使用交付的完整源码/补丁，不让小模型凭描述重写线程系统。
核心文件须成组移植：
  libavcodec/async.h、async.c：owner、有界队列、协调线程、六个公开 API。
  libavcodec/internal.h：只在 owner decoder 设置的模式位。
  libavcodec/pthread_frame.c、thread.h：早输出调度、任务计数、setup/done 唤醒。
  libavcodec/decode.c、decode.h：模式接入、fresh 生命周期检查、复用通用后处理。
  libavcodec/Makefile、version.h：构建、安装头文件、版本号。

不要删旧 ff_thread_decode_frame、参考等待或初始化依赖；不要把原始 worker
frame 绕过通用时间戳/属性/裁剪处理送 filter；不要仅把 cond_wait 改成 EAGAIN。
旧 .decode 返回值是消费字节数，不能用异步暂未完成状态替代。
完整调度解释见 doc/live-async-decoding.txt。

3. 构建与确认
-------------
Linux 依赖 GCC、GNU Make、NASM、pkg-config、Python 3、pthread。
Windows 使用 MSYS2 UCRT64 的 GCC/NASM/Make/pkg-config/Python 3。
测试脚本构建精简解码包。生产构建需保留原服务的协议、demuxer、filter、
编码器及外部库选项。机房包应在匹配发行版/glibc 的环境编译。

Linux 源码根目录：
  export FFMPEG_LIVE_BUILD_DIR="$HOME/.cache/ffmpeg-live/build-linux-async"
  export FFMPEG_LIVE_INSTALL_DIR="$PWD/../install-linux-async"
  bash tools/live-async/build-linux.sh
  export LD_LIBRARY_PATH="$FFMPEG_LIVE_INSTALL_DIR/lib"
  export PKG_CONFIG_PATH="$FFMPEG_LIVE_INSTALL_DIR/lib/pkgconfig"
  nm -D "$FFMPEG_LIVE_INSTALL_DIR/lib/libavcodec.so.61" | grep avcodec_async_

确认 create/send_packet/receive_frame/flush/get_stats/free 六个符号。
应用使用同一安装前缀的头文件与库，不与系统 FFmpeg 混用。
C++ 包含 async.h 时按项目原有 FFmpeg 方式包在 extern "C" 中。

本机 Windows PowerShell：
  & C:\msys64\usr\bin\bash.exe -lc 'export FFMPEG_LIVE_BUILD_DIR=/d/Code/ffmpeg_live/build-msys2-async; export FFMPEG_LIVE_INSTALL_DIR=/d/Code/ffmpeg_live/install-msys2-async; bash /d/Code/ffmpeg_live/ffmpeg-7.0.3/tools/live-async/build-msys2.sh'

WSL 运行 build-linux.sh 即可。Linux .so 与 Windows DLL 不能互换。
仅替换库并继续旧 send/receive，不会启用本功能。

4. 创建与所有权
---------------
保留原 demux/parser、codecpar、extradata、pkt_timebase 初始化。
在第一次送包前：

  #include <libavcodec/async.h>
  AVCodecContext *decoder = ...;     /* 已分配、复制 codecpar */
  AVCodecAsyncContext *async = NULL;
  decoder->thread_count = 12;        /* 按规格测 2/4/8/12 */
  decoder->thread_type = FF_THREAD_FRAME;
  ret = avcodec_open2(decoder, codec, NULL);
  if (ret < 0) { /* 处理失败，不继续 */ }
  ret = avcodec_async_create(&async, &decoder, 4, notify, wake_userdata);
  if (ret < 0) { /* decoder 仍归调用者；按原方式释放 */ }
  /* 成功：decoder == NULL，async 拥有并最终释放该 decoder。 */

queue_capacity=4 分别限制输入包与输出帧队列，合法 1..1024；它不是线程数，
不要求攒满。DPB、在途任务及暂存引用额外占内存，不用大队列隐藏处理不足。
LOW_DELAY 会使 FFmpeg 禁用帧线程。EINVAL 时核对 actual active_thread_type、
codec 名称、硬件上下文、get_format、是否已输入；不要盲目清空所有 flags。

转移后不得再访问/修改原 AVCodecContext。尺寸/格式取自输出 AVFrame。
所有 frontend 调用由服务同一个 owner 串行执行，不并发送包/取帧/flush/free。

5. 送包、反压与事件
------------------
  ret = avcodec_async_send_packet(async, pkt);
  if (ret == 0) av_packet_unref(pkt); /* 库持有自己的引用 */
  else if (ret == AVERROR(EAGAIN)) { /* 未接受，保留原包，等事件后重试 */ }
  else { /* EOF 或错误：走关闭/恢复流程 */ }

packet 必须正长度、完整编码访问单元、有 packet->buf。libavformat 的包通常
已引用计数；手工组包应在接收/组包阶段 make_refcounted 并检查返回值。
接口拒绝无 buf 的 packet，避免前台隐式复制整个 payload。

保留“送包后取到 EAGAIN”的基本结构，同时增加独立的完成通知入口：
  收到 packet -> 送包 -> 取到 EAGAIN -> 返回业务循环
  解码进度事件       -> 取到 EAGAIN -> 送 filter / 重试 pending packet

send 和 receive 可以同时 EAGAIN。这在本扩展中正常；不能套用旧接口的
“另一端一定马上推进”断言，不能 while(EAGAIN) 忙等。

notify 只在协调线程投递事件，不阻塞、不重入 codec/filter/生命周期 API。
通知是唤醒提示，不保证存在一帧。Linux 可使用 nonblocking eventfd：
  uint64_t one = 1;
  do { n = write(wake_fd, &one, sizeof(one)); } while (n < 0 && errno == EINTR);
  /* EAGAIN 已表示可读，不自旋；其它错误做独立故障处理。 */

事件循环读走 eventfd 计数后再取帧。level-triggered EPOLLIN 最易接入。
Windows 参考 async_probe.c 的 CreateEvent/SetEvent/WaitForSingleObject。
也可投递服务已有任务队列。若采用定时轮询，轮询间隔会计入输出时延。

6. 取帧与 filter 所有权
----------------------
  ret = avcodec_async_receive_frame(async, frame);
  /* 0 成功；EAGAIN 现在无输出、返回事件循环；EOF 排空结束。 */

成功后由原 filter owner 线程送 filter，worker 不碰 filter graph。
若 buffersrc 用 AV_BUFFERSRC_FLAG_KEEP_REF，接受成功后可以 unref 自己的帧。
若下游未接受，保存该 frame，等下游可写先重试；不能对同一个 frame 再次
receive，因为 receive 会先 unref 它，否则会丢帧。

小模型应明确维护：pending_packet、pending_frame、eof_requested、eof_sent、
decoder_eof、async owner、有效 wake userdata。事件处理先重试 pending_frame，
下游有容量再取帧，再有界重试 pending_packet；遇 EAGAIN 回到事件循环。
对积压沿用业务明确的反压策略，不偷偷扩大队列或丢弃引用帧。

7. EOF、错误、flush/free
----------------------
输入全部按序提交后，send_packet(async, NULL) 关闭输入；EAGAIN 时 NULL
尚未接受，稍后重试；0 后不再输入。持续等事件并取帧直到真正 EOF。
drain 期间 EAGAIN 正常，不能当 EOF 或触发旧接口的断言。

非 EAGAIN 的解码错误采用 fail-fast：先交付已排队输出，再报告持久错误。
恢复要 flush 或重建，并按服务策略从可解码的关键帧位置恢复，不盲目继续。
flush 丢弃在途/队列结果并等待重置，寿命计数与峰值不清零。

需要避免业务线程等 flush/free 时，先暂停该 owner 的数据操作、明确交接
所有权给维护线程；完成后再交回，不能并发调用生命周期和数据 API。
关闭先取消事件注册/停止访问，free(&async) join 后 async 为 NULL，再释放
wake userdata/关闭 eventfd。事件循环已排队旧事件需校验 owner 代次，不能
解引用已销毁指针。用户保留的输出帧仍按正常引用计数释放。

8. 测试与通过标准
----------------
使用离线包原样合成输入及原版 golden。若换编码器版本重生成，要重新生成
原版基线，不能将不同码流与旧 golden 比较。扩展样本可由
tools/live-async/generate-extra-fixtures.ps1 生成。

Linux 源码根目录：
  export FFMPEG_LIVE_INSTALL_DIR="$PWD/../install-linux-async"
  export FFMPEG_LIVE_RESULT_DIR="$PWD/../results-linux-async"
  export FFMPEG_LIVE_FIXTURE_DIR="$PWD/../results-msys2-baseline"
  export FFMPEG_LIVE_BASELINE_RESULT_DIR="$PWD/../results-linux-baseline"
  bash tools/live-async/test-async.sh

Windows 用 MSYS2 Bash 设置同名变量为 /d/...，baseline 指向
results-msys2-baseline；脚本自动选择原生 probe.exe。

通过项：
  a. H.264/HEVC，B=0/3，2/12 线程的逐帧 SHA256、PTS、DTS、时长、
     best_effort_timestamp、尺寸、格式、SAR、色彩属性与 legacy 完全相等。
  b. 像素哈希与 PTS 也匹配保存的未修改 7.0.3 基线。
  c. 首包后暂停仍可独立输出；get_buffer2 被 gate 卡住，前台仍能返回。
  d. capacity=1 反压、三次 drain/flush/replay、在途 flush/free、错误恢复。
  e. 10-bit、640x360 -> 960x540 切换、独立 intra 帧延迟完成仍保持输出顺序。
  f. peak_active_workers >= 2；该值含参考等待，不是物理 CPU 利用率或吞吐量。

summary.csv 的均值含 EOF drain 尾部；首次输出不含 demux/open 初始化时间。
不能用单路 540p 合成样本宣称业务端到端 SLA。watchdog 失败不能删掉跳过。

ASan/Leak（独立目录，禁用 asm，不用于性能比较）：
  export FFMPEG_LIVE_BUILD_DIR="$HOME/.cache/ffmpeg-live/build-linux-asan"
  export FFMPEG_LIVE_INSTALL_DIR="$PWD/../install-linux-asan"
  export FFMPEG_LIVE_RESULT_DIR="$PWD/../results-linux-asan"
  export FFMPEG_LIVE_SANITIZE=address
  export ASAN_OPTIONS=detect_leaks=1:halt_on_error=1
  bash tools/live-async/build-linux.sh
  bash tools/live-async/test-async.sh

本机 ASan/Leak 已过。禁 asm 避开 7.0.3/GCC ASan 的符号前缀探测问题。
TSan 在 WSL 的空程序阶段崩溃，未完成竞态检查；ASan 不能替代竞态检查。
捕获结果见 tools/live-async/validation/。生产验收还需真实机房 OS、真实流、
大规格、多路满载、隔行输入（如有）、网络抖动及完整 filter/编码/封装链。

9. 内网只打 core patch
--------------------
优先使用完整源码。打补丁先确认处于 n7.0.3，再：
  git apply --check ffmpeg-7.0.3-live-async-core.patch
  git apply ffmpeg-7.0.3-live-async-core.patch

补丁只含 libavcodec 核心文件；tools、指导、媒体/golden 另复制。
无 Git 的完整源码解压包可直接构建，目录结构按离线包 README 放置。
其它 7.x/8.x 不可按近似名字强行替换。自己导出补丁：
  git diff n7.0.3 -- libavcodec > ffmpeg-7.0.3-live-async-core.patch

10. 可直接交给小模型的任务
------------------------
“先读本指导与 async.h，列出服务送包/取帧/EOF/flush/free 的调用点与所有权。
接入 AVCodecAsyncContext，保留 filter 单一 owner。成功转移后不再碰旧 ctx；
packet 引用计数；send EAGAIN 保留原包；receive EAGAIN 回事件循环；接完成
通知，保证没有新包也取帧；下游不接受 frame 时保留重试；drain 等真正 EOF。
不要带入旧 EAGAIN 断言，不忙等，不在 notify 中做 codec/filter/生命周期。
按第八节测试再测真实业务流。报告修改文件、解码结果比较、时延、调用耗时、
并行证据、队列深度和未覆盖项，不把合成测试当生产验收。”
